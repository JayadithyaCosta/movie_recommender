# SPEC — Movie Recs

## 1. Product summary

Users answer a few taps ("what do you feel like right now") OR open a personalized **For You** feed, and get exactly **5 movies**, each with a poster, verified metadata, and a one-line personalized reason. Registered users build a taste profile automatically from their activity; anonymous users get the wizard only.

## 2. Modes

### 2.1 Mood wizard (`/discover`) — everyone

- Full-screen step cards from the tree in `src/config/steps.ts`. Each step: question + 2–6 large option tiles. Progress dots on top, back button, framer-motion slide transitions.
- Branching: every genre has a sub-genre step, e.g. Horror → {Ghosts & hauntings, Demons & possession, Slashers, Psychological}, Comedy → {Feel-good, Rom-com, Dark comedy, Absurd & satire} (F-14). Every branch converges on 2 shared final steps: **era** (Classics / 90s–00s / Modern / Surprise me) and **pacing** (Slow-burn / Balanced / Intense).
- Total taps: 3–4. The summary screen carries an optional free-text field ("Anything else?", max 200 chars) for constraints the tiles can't express — "nothing with jump scares", "under 2 hours". Empty by default; it never blocks the tap-only path.
- On completion → `POST /api/recommend` → redirect to `/results/[sessionId]`.

### 2.2 For You (`/for-you`) — logged in only

- Shows the user's current batch of 5 from the latest `RecSession` of type `FOR_YOU` (DB read, no LLM call on page view).
- Pull-to-refresh / "Refresh picks" button regenerates, subject to cooldown: max 1 regeneration per 12h **unless** new feedback signals exist since the last batch (then allow immediately).
- Empty state (new user, no signals): prompt them to run the wizard once — "Tell us what you feel like tonight and we'll learn from there."

## 3. Recommendation pipeline (`POST /api/recommend`)

Input: `{ answers?: WizardAnswers, mode: "WIZARD" | "FOR_YOU" }` (userId from session if present).

1. **Cache check (WIZARD + anonymous only):** `pathHash = sha256(normalized answers)`. If a `RecSession` with this hash exists < 7 days old → clone its recommendations into a new session, return. Logged-in wizard calls SKIP the shared cache (results are personalized by taste summary). Calls carrying a free-text `note` also SKIP it — the note is effectively unique, so a hash hit would serve someone else's constraints.
2. **Build prompt** from `docs/PROMPTS.md`:
   - WIZARD anonymous → Template A.
   - WIZARD logged-in → Template A + taste summary block.
   - FOR_YOU → Template B (taste summary + exclusion list).
   - Exclusion list = titles from user's past `Recommendation` rows + `MovieFeedback` rows with SEEN or NOT_FOR_ME. Cap at most recent 60 titles.
3. **LLM call** via `lib/llm`: JSON-only, zod-validate `[{title, year, reason}] x5`. One retry on parse failure with "output JSON only" reinforcement. Second failure → 502 with friendly error.
4. **TMDB resolution:** for each candidate, `GET /search/movie?query={title}&year={year}` (fallback: retry without year). Take top result with vote_count ≥ 50. Upsert into `Movie` (id = TMDB id, `raw` = full payload, refresh if `fetchedAt` > 30 days).
5. **Backfill:** if < 5 resolve, take TMDB `/movie/{id}/similar` of the highest-rated resolved pick, first result not in exclusion list, reason = "Similar to {title}, which fits your picks."
6. **Persist** `RecSession` (+ pathHash, type, answers JSON) and 5 `Recommendation` rows (rank 1–5). Return session id + enriched movie cards.

Anonymous sessions: store `sessionId`s in a signed cookie; on sign-up/login, claim them (attach userId) so history isn't lost.

## 4. Feedback & taste profile

### 4.1 Signals (`POST /api/feedback`)

Each movie card shows three one-tap actions + save:

- ❤️ LOVED, 👁 SEEN (already watched), ✕ NOT_FOR_ME → upsert `MovieFeedback`.
- Bookmark → `SavedMovie` (watchlist, shown on profile) and also records a SAVED signal.
- On NOT_FOR_ME in a For You batch: immediately call the **replace-one-pick** flow (Template D) to swap that slot; update the stored batch.
- On SEEN (F-15): same swap, with Template D's "seen" line so the replacement keeps that pick's spirit. Owner / cookie-vouched viewer only, logged-out allowed.
- "None of these? Get 5 new" (F-15, wizard/Surprise results): `POST /api/recommend {mode:"AGAIN", sessionId}` reruns the session's stored answers as a new session, current five excluded, shared path cache neither read nor written.

### 4.2 Taste profile (`lib/taste.ts`)

- `TasteProfile.genreWeights`: recomputed from wizard session history (simple frequency, decay: weight = 1 / sessionsAgo) — pure code, no LLM.
- `TasteProfile.tasteSummary`: ~80-word natural-language paragraph generated by LLM (Template C) from: genreWeights, LOVED/SAVED movie titles, NOT_FOR_ME titles, recent wizard paths.
- Regeneration trigger: `signalCount >= 5` since last regen OR `updatedAt` > 14 days — checked lazily whenever a rec pipeline call or profile page load occurs. Reset `signalCount` after regen. Never regenerate on every tap.
- Show the tasteSummary to the user on `/profile` ("Your taste, as we understand it") with a "not quite right?" → link to run the wizard again.

## 5. TMDB integration (`lib/tmdb.ts`)

- Auth: v4 read token in `Authorization: Bearer` header. Base: `https://api.themoviedb.org/3`.
- Images: `https://image.tmdb.org/t/p/w342{poster_path}` (w342 for cards, w780 for detail). Use `next/image` with the domain allow-listed.
- All TMDB fetches go through one client with: 8s timeout, single retry, and DB-backed caching via the `Movie` table. Never call TMDB from client components.
- Movie detail view (tap a card): overview, rating, runtime, genres, watch providers (`/movie/{id}/watch/providers`, region from `Accept-Language`/geo, default US) — attribute JustWatch as TMDB requires.

## 6. Auth & profile

- Auth.js v5, Prisma adapter, providers: Google (production); email magic link in dev only, printed to the server log.
- `/profile`: saved watchlist, recommendation history (sessions grouped by date), taste summary, sign out.

## 7. Failure modes (must handle)

- LLM down/unparseable after retry → **TMDB-only fallback**: `/discover` driven by the `tmdb` hints on each option in `src/config/steps.ts` (genres, keywords, era range, pacing → sort) with a 6.5 rating floor, plus templated reasons that only claim what the filter guarantees. Results are still 100% TMDB-verified (rule 1 holds); fallback sessions are tagged `answers.source = "fallback"` and never seed the shared cache.
- LLM *and* TMDB unavailable → friendly "Our film curator is napping — try again" screen with retry; wizard answers preserved in client state.
- Hard filters the LLM can't be trusted with (the era the user tapped, ±1 year) are enforced on resolved picks; rejects are backfilled.
- TMDB down → serve from `Movie` cache where possible; if a fresh session can't resolve, show error, don't show unverified LLM data.
- Rate limiting: per-IP 10 recommend calls/hour (anonymous), per-user 30/day. Upstash-style sliding window or in-DB counter.

## 8. Non-goals (v1)

No TV shows, no social features, no reviews, no multi-language UI, no React Native — PWA only.

PWA implementation note (F-13): `next-pwa` (and its forks) hook webpack, but `make build` runs Turbopack, so installability uses Next's native `src/app/manifest.ts` plus a small hand-written `public/sw.js` (cache-first static assets, stale-while-revalidate posters, network-first pages, API never cached), registered in production only.
